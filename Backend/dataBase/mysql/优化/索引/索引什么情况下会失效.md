# 缓存穿透
## 1、定义
**查询一个数据库里根本不存在的数据，绕过缓存、每次请求全打到DB上**。
缓存查不到 → 必去查MySQL，大量恶意空请求直接压垮数据库。

举例：商品id=-1、随机超长非法ID，库无这条数据，缓存永远存不到值，次次访问数据库。

## 2、产生原因
1. 恶意黑客用不存在id疯狂刷单请求
2. 业务参数错误，传非法值（负数id、乱码）

## 3、主流解决方案
### ① 缓存空值（最简方案）
DB查不到数据时，往Redis存入**空标记**，设置短过期时间。后续同请求直接命中缓存，不再查库。
优点：简单。
缺点：大量非法key会占用少量Redis内存，之后可能发生数据不一致的情况。

### ② 布隆过滤器（生产常用）
前置布隆过滤器，**所有合法id提前存入过滤器**；
请求过来先过过滤器：过滤器判定不存在 → 直接拦截，不走Redis、不走DB。
优点：拦截效率高；缺点：有极小误判概率、无法删除数据。

### ③ 参数校验
接口层提前校验：id不能负数、长度、格式非法直接拦截。

## 面试相关问题

1.  问：什么是缓存穿透？会带来什么问题？

    答：缓存穿透是指查询一个数据库中根本不存在的数据，请求会直接绕过缓存，每次都打到数据库上。大量这类请求会直接压垮数据库，造成服务不可用。

2.  问：如何解决缓存穿透？说一下常用方案？

    答：常用方案有三种：
    - 缓存空值：数据库查不到数据时，往Redis存入空标记，设置短过期时间，拦截后续相同请求。
    - 布隆过滤器：前置布隆过滤器，提前存入所有合法ID，非法请求直接拦截，不访问缓存和数据库。
    - 参数校验：在接口层提前校验参数，对负数ID、超长非法ID等直接拦截。

3.  问：缓存空值方案有什么缺点？怎么优化？

    答：缺点：
    - 大量非法key会占用Redis内存。
    - 可能出现数据不一致问题（数据库新增数据后，空标记未过期前仍会返回空）。

    优化：
    - 给空值设置较短的过期时间，减少内存占用。
    - 数据库新增数据时，主动删除对应的空值缓存，避免数据不一致。

4.  问：布隆过滤器的优缺点是什么？

    答：优点：
    - 拦截效率高，内存占用低。

    缺点：
    - 存在极小的误判概率，可能误拦截合法请求。
    - 无法删除数据，适合数据量稳定、无频繁删除的场景。
